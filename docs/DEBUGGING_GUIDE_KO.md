# 양보 및 충돌 디버깅 가이드

## 개요

이 문서는 에이전트 충돌 감지 및 양보 메커니즘의 디버깅 출력을 설명합니다.

## 출력 메시지 종류

### 1. 경로 계산 출력
```
[경로 계산] RD1: stage_RD → stage_center → main_hall_mid_left → main_hall_low_left (총 4칸)
```

**의미:**
- 에이전트가 새로운 경로를 계산할 때 출력
- 경로의 시작점부터 끝점까지 모든 노드를 화살표(`→`)로 연결하여 표시
- 총 칸수를 표시 (경로의 길이)

**예시 분석:**
- `RD1`: 에이전트 이름
- `stage_RD → stage_center → main_hall_mid_left → main_hall_low_left`: 이동 경로
- `총 4칸`: 이 경로는 4개의 노드를 거침

---

### 2. 충돌 감지 출력
```
[충돌 감지] RD2가 Left_door로 가려하는데 RD1이 Left_door에 있음
```

**의미:**
- 에이전트가 다음 노드로 이동하려 했으나 다른 에이전트가 그 위치를 점유 중일 때 출력
- 이는 **deadlock 상태의 시작**을 의미

**상황 분석:**
```
RD2의 경로: ... → Left_hall_mid_low → Left_door → ...
RD1의 위치: Left_door (정지 중)

RD2는 Left_door로 가려하지만 RD1이 있어서 못 감
→ 충돌 감지!
```

---

### 3. 양보 요청 및 선택 과정

#### 3-1. 양보 대상 선택 (양보 대상 분석)
```
[양보 대상 선택] Left_hall_mid_low ← RD2 (거리:1, 근처) | 검토:15, 필터:7, 유효:8
```

**의미:**
- 양보할 때 어느 위치로 이동할지 선택하는 과정
- 선택된 위치와 그 특성을 표시

**필드 설명:**
| 필드 | 의미 | 예시 |
|------|------|------|
| `Left_hall_mid_low` | 선택된 양보 위치 (노드명) | 에이전트가 여기로 이동 |
| `RD2` | 양보하는 에이전트 | 우선순위가 낮아서 양보함 |
| `거리:1` | 현재 위치에서 양보 위치까지의 거리 | 1칸 떨어져 있음 |
| `근처` | 위치 분류 | "근처"(1-2칸), "경로상", "경로외" 중 하나 |
| `검토:15` | 검토한 후보 노드 수 | 총 15개 노드를 검토함 |
| `필터:7` | 제외된 노드 수 | 금지 구역 등으로 7개 제외 |
| `유효:8` | 실제 사용 가능한 노드 수 | 8개가 조건을 만족함 |

**우선순위 해석:**
1. **"근처" (거리 1-2)** - 가장 선호됨
   ```
   현재 위치에서 1-2칸만 떨어진 곳
   → 빨리 비워지므로 상대방이 빨리 지나갈 수 있음
   ```

2. **"경로상"** - 차선책
   ```
   원래 가려던 경로 상의 노드
   → 양보 후 쉽게 원래 경로로 돌아올 수 있음
   ```

3. **"경로외"** - 마지막 선택지
   ```
   아무 상관없는 다른 지역
   → 보통 이것은 피해야 함 (불필요한 우회)
   ```

#### 3-2. 양보 선택 실패
```
[양보 대상 선택 실패] 검토:20개, 필터:18개, 유효:2개, 경로상:0개
```

**의미:**
- 양보할 적절한 위치를 찾지 못함
- 주변이 모두 금지 구역이거나 다른 에이전트로 가득 찼을 수 있음

**해석:**
- `검토 20개` 중 `필터 18개` 제외 = 조건을 만족하는 곳이 거의 없음
- `유효 2개`만 남았는데 그중 `경로상 0개` = 원래 경로와 무관한 곳만 가능
- **이것은 설계 문제일 수 있음** (맵이 너무 좁거나 에이전트가 너무 많음)

---

### 4. 양보 실행 단계

#### 4-1. 양보 성공
```
[양보 성공] RD2 → RD1 (양보자: RD2, 목표: Left_hall_mid_low)
```

**의미:**
- 양보 요청이 수락됨
- 에이전트가 실제로 이동을 시작함

**상황 진행:**
```
1. RD2가 Left_door로 가려고 함
2. 충돌 감지 → RD1이 있음
3. 우선순위 결정 → RD2가 양보하기로 함
4. 양보 위치 선택 → Left_hall_mid_low로 결정
5. 양보 성공! RD2는 이제 Left_hall_mid_low로 이동 중
```

#### 4-2. 양보 거부
```
[양보 거부] RD2가 양보를 거부함 (목표: Left_hall_mid_low)
```

**의미:**
- 양보 위치로 이동하려 했으나 실패
- 그 사이에 다른 에이전트가 그곳을 점유했을 가능성

---

### 5. 양보 수락 시 상세 정보
```
[양보 수락] RD2가 Left_door에서 Left_hall_mid_low로 양보 (원래 목표: stage_RD, 대기시간: 1.5초)
```

**의미:**
- 에이전트가 양보 위치로 이동하기 시작
- 원래 목표로 돌아갈 시간까지 표시

**필드 설명:**
| 필드 | 의미 |
|------|------|
| `Left_door` | 현재 위치 |
| `Left_hall_mid_low` | 양보 위치 (이동할 곳) |
| `stage_RD` | 원래 최종 목표 |
| `1.5초` | 양보 위치에서 대기할 시간 |

---

### 6. 양보 완료 및 복귀
```
[양보 완료] RD2가 원래 목표 stage_RD로 복귀
```

**의미:**
- 대기 시간이 끝남
- 에이전트가 원래 가던 목표로 다시 이동을 시작

**시간 흐름:**
```
1. [양보 수락] ... (대기시간: 1.5초)
2. (1.5초 대기 중)
3. [양보 완료] RD2가 원래 목표 stage_RD로 복귀
4. [경로 계산] RD2: Left_hall_mid_low → ... → stage_RD (새로운 경로)
```

## 전체 흐름 예시

다음은 한 번의 양보 사이클 전체 출력입니다:

```
[경로 계산] RD1: stage_RD → stage_center → main_hall_mid_left → main_hall_low_left (총 4칸)
[경로 계산] RD2: Left_hall_coner → Left_door → Left_hall_mid_low → Storage_front (총 4칸)

--- 시간 경과: 양보 발생 ---

[충돌 감지] RD2가 Left_door로 가려하는데 RD1이 Left_door에 있음
[양보 대상 선택] Left_hall_mid_low ← RD2 (거리:1, 근처) | 검토:15, 필터:7, 유효:8
[양보 성공] RD2 → RD1 (양보자: RD2, 목표: Left_hall_mid_low)
[양보 수락] RD2가 Left_door에서 Left_hall_mid_low로 양보 (원래 목표: Storage_front, 대기시간: 1.5초)

[경로 계산] RD2: Left_door → Left_hall_mid_low (양보 경로, 총 2칸)

--- 시간 경과: RD1이 지나감 ---

[경로 계산] RD2: Left_hall_mid_low → Storage_front (복귀 경로, 총 2칸)
[양보 완료] RD2가 원래 목표 Storage_front로 복귀
```

## 문제 진단 가이드

### 문제: "Left_door까지 갈 필요가 없는데 갔다가 다시 돌아옴"

**진단 과정:**

1. **출력에서 확인하는 것:**
   ```
   [충돌 감지] RD2가 Left_door로 가려하는데 RD1이 Left_door에 있음
   [양보 대상 선택] Left_hall_mid_low ← RD2 (거리:5, 경로외)
   ```
   - `거리:5` → 현재 위치에서 5칸 떨어짐 = **너무 멀다!**
   - `경로외` → 원래 경로와 무관한 곳 = **불필요한 우회**

2. **원인 분석:**
   - 양보 대상 선택 로직이 "경로상의 노드"만 찾으려 했는데
   - 경로상 노드가 너무 멀어서 (또는 금지되어서) 경로외 노드를 선택

3. **해결책:**
   - 알고리즘이 개선됨: 이제 "거리 1-2" 근처를 최우선으로 선택함
   - 위의 출력에서 `근처`가 나오면 문제가 해결된 것

## 테스트 방법

### 1. 콘솔 출력 확인
```
1. 게임 실행 (F5 또는 ▶)
2. 에이전트들이 이동할 때까지 기다리기
3. 다음을 찾으면 문제 발생:
   - [양보 대상 선택] ... (거리:3 이상, 경로외)
   - [양보 대상 선택 실패]
4. 다음이 보이면 정상:
   - [양보 대상 선택] ... (거리:1-2, 근처)
```

### 2. 에이전트 이동 관찰
```
✓ 정상 동작:
  - 에이전트 A가 이동 중
  - 에이전트 B가 앞에 있음 (충돌)
  - A가 1칸 옆으로 물러남 (양보)
  - B가 지나감
  - A가 원래 경로로 계속 이동

✗ 문제 상황:
  - A가 양보하려고 멀리 돌아감 (unnecessary detour)
  - A가 양보 위치에서 오래 머물러 있음
  - A가 쓸데없이 딴곳을 거쳐감
```

### 3. 성능 확인
```
콘솔 통계:
  [양보 대상 선택] ... | 검토:15, 필터:7, 유효:8
  
정상 범위:
  - 검토: 10-20 (노드 개수에 따라 다름)
  - 필터: 40-60% 정도
  - 유효: 적어도 2-3개 이상
  
문제 상황:
  - 필터가 90% 이상 (거의 모든 곳이 금지)
  - 유효가 0-1개 (선택지가 없음)
```

## 알고리즘 개선 사항

### 이전 로직 (문제)
```
양보 위치 선택:
1. 경로상의 노드 찾기 (거리 상관없음)
2. 없으면 가장 가까운 노드

결과: Left_door → Left_hall_mid_low → Storage_front
까지 가야 하는 경우, Storage_front를 선택할 수 있음 (경로상)
→ 불필요한 우회!
```

### 현재 로직 (개선)
```
양보 위치 선택 우선순위:

Tier 1: 아주 가까운 곳 (거리 1-2)
  → 이것을 최우선으로 선택!
  → 빨리 비워지므로 상대방도 빨리 지나갈 수 있음

Tier 2: 경로상의 노드 (거리 3+)
  → 경로를 벗어나지 않음

Tier 3: 모든 노드 (거리 상관없음)
  → 마지막 수단

결과: 가장 가까운 안전한 곳으로 이동
→ 빠른 양보와 빠른 복귀!
```

## FAQ

### Q: "[양보 대상 선택 실패]"가 자주 나옵니다
**A:** 
- 맵이 너무 좁거나 에이전트가 많을 가능성
- 충돌 회피 거리(YIELD_MIN_CONFLICT_DISTANCE)를 줄일 수 있음
- 또는 에이전트들의 우선순위를 재조정

### Q: "경로외"로 계속 양보합니다
**A:**
- "근처"(거리 1-2) 옵션이 없다는 뜻
- 블로커 주변이 모두 금지 구역일 가능성
- 맵의 노드 배치를 검토하거나 YIELD_SEARCH_DEPTH를 증가

### Q: 양보 후 원래 경로로 돌아오지 않습니다
**A:**
- 콘솔에서 "[양보 완료]" 메시지를 찾기
- 없으면 대기 시간(WAIT_STEP_SECONDS) 동안 다른 충돌이 발생했을 수 있음
- 우선순위 시스템 재확인

